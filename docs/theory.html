Theory Overview

Open the slides ↗ Download self-contained deck

Ten chapters, storyboard-narrated, ≈240 minutes of contact time.

Chapters

01 · What is Machine Learning? · 25 min

By the end of this chapter, students can:

  1. Frame an applied (clinical) problem as a machine-learning problem by specifying its Task (\(T\)), Performance measure (\(P\)), and Experience (\(E\)), following Mitchell’s definition.
  2. Contrast machine learning with traditional programming, stating for each what is provided as input and what is produced as output (in ML the algorithm is the output, learned from \(\text{training data}\), modelling \(Y \simeq f(X)\)).
  3. Classify a described scenario into the correct learning paradigm — unsupervised, supervised, active, or reinforcement — and justify the choice from the kind and availability of supervision/labels.

02 · Classifiers · 20 min

By the end of this chapter, students can:

  1. Distinguish a classification task from a regression task by the type of output it produces — a discrete class label vs a continuous value — and identify which one a given clinical task requires.
  2. Represent a classifier geometrically as a function \(f:\mathbb{R}^d \to \{1,\ldots,K\}\) that partitions the feature space into decision regions (one region per class).
  3. Apply the 0/1 loss to a classifier’s predictions and interpret its risk as the expected loss \(\text{risk}(f) = \mathbb{E}[\mathfrak{L}(f(X), Y)]\) — the quantity that training seeks to minimise.

03 · Algorithm examples · 35 min

By the end of this chapter, students can:

  1. Compare three algorithm families — \(k\)-Nearest Neighbor, linear / Support-Vector Machine, and ensemble (Random Forest) — by the shape of the decision regions each one carves in the feature space: data-defined neighbourhoods around training points (\(k\)NN), a maximum-margin hyperplane \(f(x) = \text{sgn}(w^\top x + b)\) optionally through a kernel-induced feature map (SVM), or many axis-aligned cuts combined by majority vote (RF). Each shape is the kind of boundary that family of algorithm is capable of producing.
  2. Explain the kernel trick operationally: a non-linear feature map \(\phi:\mathbb{R}^d \to \mathbb{R}^D\) — e.g. \((y_1, y_2) \mapsto (y_1^2,\ y_2^2,\ \sqrt{2}\,y_1 y_2)\) — can turn a non-linearly-separable dataset into a linearly-separable one, without changing the linear classifier itself; only what the classifier sees changes.
  3. Predict how the accuracy of a majority vote of \(m\) independent weak classifiers with per-classifier accuracy \(p\) behaves as \(m\) and \(p\) vary, and state why the construction only improves on a single classifier when \(p > 0.5\).

04 · Model selection & validation · 30 min

By the end of this chapter, students can:

  1. Diagnose overfitting from the signature low training error + high error on new data: name the phenomenon, and state its cause — the model has captured idiosyncrasies of the training sample, not the underlying signal the task wants to learn — rather than a fault of the algorithm itself.
  2. Apply the train / validation / test split to a model-selection task: assign each subset its role — training fits the model’s parameters, validation chooses between candidate models / hyperparameter settings, test (held out) estimates the final model’s performance on truly unseen data — and state explicitly why the same data cannot be used both to choose a model and to estimate its performance (every decision taken after looking at a number on a dataset contaminates that number as a future estimate).
  3. Use \(K\)-fold cross-validation as the practical procedure for the validation step: state the algorithm — split the (non-test) data into \(K\) equal blocks; for \(k = 1, \ldots, K\) train on the remaining blocks and estimate error on block \(k\); average the \(K\) errors — identify what the CV error rate estimates (the prediction error of the chosen model on unseen data), and recognise that \(K \in [5, 10]\) is the standard range (smaller \(K\) over-trains, larger \(K\) adds variance).

05 · Deep Learning · 25 min

By the end of this chapter, students can:

  1. Describe an artificial neuron as a generalised non-linear logistic unit: given a vector of inputs \(a = (a_1, \ldots, a_n)\) and weights \(w = (w_1, \ldots, w_n)\), the neuron computes \(\text{out} = g\!\left(\sum_{i=1}^{n} a_i \, w_i\right)\), where \(g:\mathbb{R}\to\mathbb{R}\) is a non-linear and differentiable activation function — i.e. an old logistic regression in which the sigmoid has been replaced by any such \(g\).
  2. Compose the forward pass of a small fully-connected (MLP) network: given an architecture spec — number of inputs, number of hidden layers and neurons per layer, output neuron — write the per-layer equations \(a^{[l]} = g\!\left(W^{[l]} \, a^{[l-1]}\right)\), identify the activation \(g\) at each layer, and count the total number of weights the network has to learn.
  3. Explain how the network learns: the weights \(W\) are the parameters; each combination of \(W\) yields a single loss value \(L(W)\) — the height on an error landscape; gradient descent updates \(W \leftarrow W - \eta \, \nabla_W L(W)\) to walk downhill — and state why the activation \(g\) must be differentiable (so \(\nabla_W L\) exists at every \(W\) and descent is well-defined) and non-linear (so a stack of layers can do more than one big linear map).

06 · Unstructured data (CNN/RNN) · 20 min

By the end of this chapter, students can:

  1. Match an unstructured-data type to the right deep architecture and justify the choice in one sentence: multi-dimensional spatial single-information (e.g. a chest X-ray, a CT slice) → Convolutional Neural Network (CNN) because the signal of interest is a local spatial pattern that can appear anywhere in the image, and CNNs encode this via a small kernel slid over the input; one-dimension privileged sequential single-information (e.g. an ECG trace, a clinical note, a heart-rate time series) → Recurrent Neural Network (RNN) because the order of the elements carries information, and RNNs encode this via a hidden state propagated from one position to the next.
  2. Describe the convolution operation on a 2D input: a small kernel \(K \in \mathbb{R}^{k \times k}\) (e.g. \(3 \times 3\)) is slid over the input image \(X\); at each position \((i, j)\) the output feature map is \(F_{ij} = g\!\left(\sum_{u=1}^{k} \sum_{v=1}^{k} K_{uv} \, X_{i+u-1,\, j+v-1}\right)\). Then explain — as the core reason CNNs exist — that the same kernel is reused at every spatial position (weight sharing) and is therefore much smaller than a fully-connected layer would be on the same input: a \(3 \times 3\) kernel scanning a \(224 \times 224\) image has \(9\) weights to learn instead of the \(\approx 50\,000\) a single fully-connected neuron would need over the same input.
  3. Describe the recurrent operation on a sequence: at each position \(t = 1, \ldots, T_x\) the network updates a hidden activation \(a^{<t>} = g\!\left(W_{aa} \, a^{<t-1>} + W_{ax} \, x^{<t>} + b_a\right)\) and emits an output \(y^{<t>} = g'\!\left(W_{ya} \, a^{<t>} + b_y\right)\). Then explain — as the core reason RNNs exist — that the same matrices \(W_{aa}, W_{ax}, W_{ya}\) are reused at every position \(t\) (weight sharing across time), which (a) makes the parameter count independent of the sequence length \(T_x\), and (b) lets the hidden state \(a^{<t>}\) act as the network’s memory of everything it has read so far.

07 · LLMs & Transformers · 25 min

By the end of this chapter, students can:

  1. Decode the acronym Chat-G-P-T backwards, naming for each letter the technical contribution that letter encodes: T = Transformer (the 2017 Attention is all you need architecture — encoder/decoder built around the self-attention mechanism, in which every token’s representation is computed as a weighted combination of every other token in the input, in parallel); P = Pre-trained (the model has already learned a general-purpose statistical model of language by reading a massive corpus, before it sees any user task); G = Generative (at inference the model produces the next token by sampling from \(p(\text{token} \mid \text{prompt})\) and then feeds that token back as input — autoregressive generation, one token at a time); Chat (the model is wrapped in a multi-turn dialogue protocol that keeps the conversation as part of the prompt). A student who can match each letter to its contribution understands what kind of object an LLM is before asking what it can do.
  2. Contrast the Transformer’s self-attention with the RNN’s sequential hidden state from ch 06, on a sequence of length \(T_x\): the RNN computes \(a^{<t>} = g(W_{aa} a^{<t-1>} + W_{ax} x^{<t>} + b_a)\) — position \(t\) cannot be computed until position \(t-1\) has been computed (the loop is serial), and the dependency between position \(1\) and position \(T_x\) has to travel through \(T_x - 1\) intermediate states; the Transformer instead computes \(\text{attention}(Q, K, V) = \text{softmax}\!\left(\dfrac{Q K^{\top}}{\sqrt{d_k}}\right) V\) where every position attends to every other position in one shot, in parallel, so the dependency between position \(1\) and position \(T_x\) is one operation away. State, as the core reason Transformers replaced RNNs, that this turns sequence modelling into a problem of matrix multiplication, which scales on GPUs in a way that the RNN’s sequential loop cannot.
  3. Explain transfer learning as the operational meaning of “Pre-trained”: a single very expensive pre-training run on a massive generic corpus produces a model that already knows the general statistics of language; a much cheaper fine-tuning step adapts this model to a specific task (e.g. discharge-letter summarisation, ICD coding) using a small task-specific dataset. State the cost/benefit clearly: fine-tuning needs orders of magnitude less data and compute than training from scratch — and that is what makes biomedical applications of LLMs realistic at all.

08 · Using ChatGPT in practice · 15 min

By the end of this chapter, students can:

  1. Construct a structured prompt for a given clinical task using the 7-slot template — role (who the model is impersonating), context (the situation the task lives in), task (the one verb the model must perform), instructions (the procedure to follow), output (the exact shape of the deliverable), style (constraints on tone, format, what not to add), examples (1–3 worked input/output pairs) — and justify in one line, for each slot they used, why that slot is load-bearing for the task at hand (i.e. which failure mode is suppressed by that slot).
  2. State and apply the competence rule: only delegate to an LLM tasks whose answer you can independently judge as correct or wrong. Concretely: given a candidate task, identify (a) a plausible-looking failure mode the model could produce (e.g. a fabricated citation, a wrong dosage rounded to a plausible number, a hallucinated guideline), and (b) the expertise (clinical / methodological / statistical) the user must already have to catch that failure. If the user does not have that expertise, the task is not delegable.
  3. Choose the right access mode (Web chat / Prompt design / API) for a given workflow and estimate its token cost using the rule of thumb \(1\) token \(\approx \dfrac{3}{4}\) word (i.e. \(\sim 750\) words \(\approx 1\,000\) tokens, \(\sim 750\,000\) words \(\approx 10^6\) tokens). State the decision rule: Web for ad-hoc one-shot questions, Prompt design (still in chat) for a small batch of repeated structured tasks done by hand, API for any workflow that must be repeatable, integrated into other software, or applied at volume (\(\gtrsim 100\) items).

09 · Agents · 15 min

By the end of this chapter, students can:

  1. Distinguish an agent from a plain chat-LLM by naming the three additional ingredients an agent has: (a) tools the model can invoke (web search, calculator, file-system access, mail client, browser, API call, …); (b) a control loop that, after every model response, decides which tool to call next, or whether to stop; (c) decision points at which the agent either acts autonomously, asks the human for input, or shares state with the human. State the operational consequence: in a chat, every output reaches a human before it becomes an action; in an agent, some outputs become actions without a human reading them first.
  2. Map the four interaction modes introduced in the slides — autonomous search (the agent gathers information on its own), ask for interaction (the agent stops and asks the human a question to disambiguate), ask for sharing (the agent asks the human to provide credentials, access, or a resource), do stuff (the agent performs an action with external effect) — to the two axes that define the trust boundary: (i) reversibility — can this action be undone in \(30\) seconds by closing a tab, or does it persist (email sent, file deleted, record written to an EHR)?; and (ii) human-in-the-loop — did a human read the agent’s reasoning before the action happened?. A mode is “safe by default” if it is either reversible or human-in-the-loop; it is “dangerous by default” if it is neither (i.e. do stuff on an irreversible target without a confirm step).
  3. Place the trust boundary in a small clinical-research workflow: given a multi-step task (e.g. “find the latest guidelines, summarise them, draft a one-page protocol, email it to the PI”), decide for each step whether the agent may act autonomously, must ask, must share, or must hand back — and justify the boundary using the reversibility criterion (“I let the agent search, summarise, and draft autonomously because all three are reversible; I require an ask-step before sending the email because email is irreversible”).

10 · Best practices for ML projects · 15 min

By the end of this chapter, students can:

  1. Plan a first iteration of an ML project as the simplest model on the smallest sensible feature set, and write an explicit stop-criterion before adding complexity. Concretely, given a problem and a dataset, state (a) the baseline model (e.g. logistic regression on \(5\)–\(10\) features), (b) the baseline metric and the target value that would make the simple model “good enough”, and (c) the single failure mode that would justify increasing model complexity — and not before. State the rationale in one sentence: more parameters and richer features are paid for in robustness, interpretability, and risk of overfitting — so each added unit of complexity must be earned by a failure of the simpler model.
  2. Choose metrics for the problem you actually have, not for the problem accuracy assumes you have. Apply two rules: (R1) on an imbalanced problem with positive-class prevalence \(p\) (e.g. \(p = 1\%\), a rare event), reporting accuracy is misleading because the always-predict-majority classifier reaches accuracy \(= 1 - p = 99\%\) while being clinically useless — use precision, recall, F1, or AUPRC instead, and pick the threshold deliberately based on the clinical cost of false positives vs false negatives. (R2) the data-leakage rule: any decision (model choice, hyperparameter, feature set, threshold) that is taken after having seen a performance number on a dataset converts that dataset into a training set — even if the file is labelled “test”. A faithful test set is one that has been looked at exactly once, at the end, and never again.
  3. Match the interpretability technique to the model family, and weigh the interpretability/performance tradeoff in a healthcare deployment context. The mapping: linear / logistic regression → read off the coefficients (each one is the log-odds change per unit of feature, with sign and magnitude); decision tree → read off the decision path (a sequence of human-readable if-then rules); random forest / gradient boosting → use variable importance (which features the ensemble relies on most); neural network / deep model → use SHAP (per-sample additive attribution) or surrogate models. State the operational rule for healthcare: if the deployment requires clinical defensibility (e.g. a clinician must justify a single recommendation to a patient), prefer a model whose interpretability is built-in (linear or single tree) — unless the performance gap to the opaque model is large enough that the patient is better off with the box-with-SHAP than with a simpler model that misclassifies more often. The tradeoff is a clinical decision, not a technical one.

Total contact time: 225 min.
