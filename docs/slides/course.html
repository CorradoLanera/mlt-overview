What we are going to see

Purpose of this class is to introduce what is Machine Learning — what are the techniques involved, how they work, and how to understand (and trust) their results. We’ll also look at some examples and best practices in conducting a machine-learning project.

The class will cover from simple classical techniques to large language models, including agents.


My principal aim is to give you the tools to start understanding and evaluating the quality of a machine-learning project when used for clinical purposes, possibly regardless of its complexity.

Two ways of writing software

Traditional programming

  • you write the rules (algorithm)
  • you provide input data
  • you obtain the answer

Machine learning

  • you provide training input (data)
  • you provide training answers (labels)
  • you obtain the rule itself: \(Y \simeq f(X)\) (only approximate — data is noisy)

Stessi blocchi, frecce invertite: l’algoritmo è output. La \(f\) in \(Y \simeq f(X)\) si impara dal training.

Take-away (a voce): il ML è ottimizzazione, non programmazione esplicita.

Warning: unbalanced data need balanced metrics

  • Accuracy = \(\dfrac{\text{correctly classified}}{\text{total}}\)
  • On rare outcomes (\(\sim 5\%\)) the trivial “always-negative” classifier scores ~\(95\%\) accuracy and misses every real case.
  • We will need other measures (and other procedures — chapter 04) to do better.

Qui solo seminare: accuracy non basta. Le metriche (sens/spec, AUC, balanced acc) NON si insegnano ora → gancio al cap. 04.

Task · Performance · Experience: that’s the whole machine.

Mitchell 1997. Tre coordinate: \(T\) compito, \(P\) misura, \(E\) dati.

Punto da far atterrare: nominare \(T/P/E\) di un sistema = metà del lavoro per giudicarlo.

Mitchell’s definition

“A computer program is said to learn from experience (\(E\)) with respect to some class of tasks (\(T\)) and performance measure (\(P\)), if its performance at tasks in \(T\), as measured by \(P\), improves with experience \(E\).”

— Tom Mitchell, Machine Learning, 1997

Punto: learning = \(P\) su \(T\) migliora al crescere di \(E\). Non “diventare intelligente”: è un numero che sale.

\(T\) — the task

Learning problem Task \(T\)
Predict 30-day readmission classify patients as will / will-not be re-admitted
Handwriting recognition recognise / classify handwritten characters in images
Self-driving car drive from A to B
Disease coding from EHR classify EHR notes by reported disease
In-bed patient monitoring output position + dynamics at any given time

Distinzione a voce: il task è cosa fa su un nuovo input, non il training. Il training produce il modello; il task è del problema, non del processo.

\(P\) — the performance measure

Task \(T\) Performance \(P\)
classify readmission yes/no \(\%\) correctly classified (needs a balanced metric — class imbalance; ch. 4)
classify handwritten characters \(\%\) correctly classified
drive A → B average distance driven before a human intervention
classify EHR by disease \(\%\) of EHRs correctly classified
monitor in-bed dynamics average error on position / dynamics

\(P\) = un numero, compatibile con output e distribuzione delle classi.

Richiamo beat 3: su esiti rari “\(\%\) correctly classified” non basta (95% trivial-accuracy).

\(E\) — the experience (the data)

Task \(T\) Experience \(E\)
classify readmission EHR records with known re-admission outcomes
recognise handwriting labelled images of handwritten characters
drive A → B sequence of videos + steering commands from human drivers
classify EHR by disease EHR notes with known disease labels

Where do the labels come from?

Domanda-chiave che smista i 4 tipi. È anche la chiave del sommativo: dove sono le label e quando arrivano → paradigma.

Four kinds, in box order

  • Supervised (tag) — inputs come with their correct outputs (the labels); the model learns from its errors on them.
  • Unsupervised (pattern) — input data has no labels; the model finds patterns / clusters on its own.
  • Active (raised hand) — the model queries an oracle (e.g., a clinician) to label the cases it is most uncertain about.
  • Reinforcement (trophy) — an agent takes actions and receives rewards; it learns a policy that maximises long-term gain.

Ricucire alle 4 icone della slide precedente (da sinistra): tag → supervised, pattern → unsupervised, mano alzata → active, trofeo → reinforcement.

Aside da far atterrare: nessuno è “meglio” — dipende dal problema.

Item 01 — Question

A hospital deploys a model that predicts 30-day readmission from each patient’s EHR. Which statement best captures how this machine-learning system differs from a traditional, rule-based program written for the same task?

  • A) In traditional programming an engineer writes the decision rules and the program applies them to data; in machine learning the rules — the model — are learned from data paired with known outcomes.
  • B) Machine learning needs no data, whereas a traditional program requires data as input.
  • C) A traditional program can only handle numeric inputs, while machine learning is the only approach able to process patient records at all.
  • D) Machine learning is guaranteed to be more accurate than any hand-written rule, because learning from data removes human bias.

Item 01 — MCQ Comprehension, low–medium. Obj. 2 (ML vs programmazione tradizionale). ~60s.

Ref: course/01-introduction/items/item_01_ml-vs-programming_mcq.md.

Item 01 — Solution (write yours)

Slide bianca. 60-90s per scegliere A/B/C/D, poi accolgo l’opzione più votata e la giustifico. Avanzo al consenso.

Item 01 — Solution

Correct: A. The defining difference is the input/output swap. In ordinary software the rules are the input (hand-written) and answers come out; in ML you provide the data and the known answers, and the model — the rule \(Y \simeq f(X)\) — is the output, learned from training data.

Why the distractors are wrong:

  • B inverts the dependency: ML is more data-dependent, not less.
  • C is a false capability claim: rule-based programs can process records too; data type is not what distinguishes the two approaches.
  • D is the “ML is objective / always better” misconception: a model can score 95% accuracy and still be clinically useless on imbalanced data, and it inherits whatever bias is in its training data.

Rinforza beat 2. Se scelgono D → gancio all’accuracy trap del beat 3 (95% trivial-accuracy).

An ICU team wants a system that, at admission, predicts whether a patient will develop sepsis during their ICU stay.   2. Balanced accuracy = average of the model’s accuracy within each class. Consider a trivial model that predicts “no sepsis” for every patient. (a) What is its plain accuracy, and its balanced accuracy? (b) Use your answer to explain why balanced accuracy is the more appropriate choice of \(P\).

Item 02 — Solution

Framing

  • \(T\): predict, at admission, whether a patient will develop sepsis during the ICU stay — binary classification.
  • \(P\): balanced accuracy (rather than plain accuracy).
  • \(E\): past ICU admissions labelled with whether sepsis occurred — supervised experience.

The revealing computation

  • (a) “Always no-sepsis” model: correct on 96% of patients ⇒ plain accuracy ≈ 96%. Accuracy on sepsis class = \(0\%\); on non-sepsis = \(100\%\). ⇒ Balanced accuracy = (0% + 100%) / 2 = 50%.
  • (b) Plain accuracy is inflated by the 96% majority of negatives, so a clinically useless model still scores ≈ 96%. Balanced accuracy weighs the two classes equally; missing the rare class drags it to chance (50%) — honestly revealing the model is useless for the task that matters.

Grading: balanced accuracy è definita nell’enunciato → valutare il ragionamento, non il vocabolario. “50% = no better than chance” con altre parole = già Good.

Which learning paradigm best describes this set-up?

  • A) Supervised learning, because the model is ultimately trained on radiologist-labelled X-rays.
  • B) Active learning, because the model repeatedly queries an expert (the oracle) to label the cases it is most uncertain about.
  • C) Reinforcement learning, because the model improves over repeated cycles by interacting with its environment.
  • D) Unsupervised learning, because the model scans many X-rays that have no labels.

Item 03 — Solution

Correct: B — Active learning.

The defining feature is the loop in which the model itself chooses which unlabelled cases to send to a human oracle for labelling — selective querying is active learning.

Why the distractors are plausible but wrong:

  • A — the underlying model is a supervised classifier, but “supervised” alone misses what distinguishes the scenario: the model’s selective request for labels. Active learning is a strategy built on top of supervised learning.
  • C — confuses “repeated cycles” with reinforcement learning. RL requires a reward signal guiding actions; here there is no reward, only requested labels.
  • D — many X-rays are unlabelled, but the model is trained on labels (just sparingly requested), so it is not unsupervised.

Take-away: active = supervised + scelta delle label da richiedere. Se serve, link allo scenario D del sommativo (disease coding): stesso schema.

Item 04 — Solution

  1. The ICD-codes proposal does not achieve the goal. ICD codes are pre-existing, human-defined diagnostic categories — not the previously unrecognised subgroups the task asks to discover. A supervised classifier trained on them would only learn to reproduce labels that already exist; it cannot surface new structure. “Labels available” ≠ “labels that match the goal.”

  2. Unsupervised learning (clustering) fits the goal: discover structure / subgroups in data that carry no labels for the thing being sought (the phenotypes).

  3. The colleague’s supervised approach would be exactly right under a different goal: predicting a patient’s existing ICD diagnosis from their lab panels. There the ICD codes are legitimately the target labels, and assigning new patients to known categories is supervised classification.

Payoff: separare goal vs availability of labels. Grading: premiare la coerenza, non le keyword (“clustering”/“unsupervised”/equivalenti valgono uguale).

Classification vs regression — the single discriminator

Output Lives in Example
Classification a label (discrete) \(\{1, \ldots, K\}\) “high-risk or low-risk?”
Regression a value (continuous) \(\mathbb{R}\) “predict HbA1c (%) at 6 months”

Punto unico da far atterrare: discrimina l’output, non l’input. Anche se il modello calcola un punteggio interno, conta l’output finale. (Il punteggio lo apriamo al beat espansione.)

No line catches them all.

Da dire a voce: il rischio minimo è strutturalmente \(> 0\) — non difetto dell’algoritmo, proprietà dei dati. Le classi reali si sovrappongono.

A classifier splits the space into regions.

Formalmente il classificatore è una funzione \(f:\mathbb{R}^d \to \{1,\ldots,K\}\) che taglia lo spazio in regioni — una per classe. Il confine È il classificatore: cambia il confine, cambia il classificatore.

A classifier is a function on the feature space

For features \(X \in \mathbb{R}^d\) and \(K\) classes, a classifier is a function \[f : \mathbb{R}^d \to \{1, \ldots, K\}.\]

  • Every point of \(\mathbb{R}^d\) is sent to exactly one class — no gaps, no overlaps.
  • The decision regions are the preimages \(f^{-1}(1), \ldots, f^{-1}(K)\).
  • The boundary between regions IS the classifier (Obj. 2).

Punto chiave: “\(f\) è un classificatore” e “le regioni partizionano \(\mathbb{R}^d\)” sono lo stesso enunciato — non due cose diverse. Questo è il fulcro dell’item 02 (Partition the plane).

…but the label is usually a thresholded probability

So far we have read a classifier’s output as a hard label. But that label is rarely produced directly: most “classifiers” first estimate a probability, then cut it at a threshold (binary task: \(K = 2\), labels \(\{0,1\}\), \(1 =\) positive):

\[g : \mathbb{R}^d \to [0, 1], \qquad g(x) = \widehat{P}(Y = 1 \mid X = x).\]

\[f_\tau(x) = \begin{cases} 1 & \text{if } g(x) \ge \tau \\ 0 & \text{otherwise,} \end{cases} \qquad \tau = 0.5 \text{ by default.}\]

  • The model that is actually fit is the continuous \(g\) — a regression onto \([0, 1]\). The hard label appears only once we pick a threshold \(\tau\).
  • One \(g\) therefore spawns a whole family of classifiers \(\{f_\tau : \tau \in [0, 1]\}\) — one per cut, each making different mistakes.
  • The habitual \(\tau = 0.5\) is a convention — natural only when the two kinds of error cost the same (and \(g\) is well-calibrated) — not a clinical law: when a missed case costs more than a false alarm, the best cut moves.

So two different things deserve evaluation — the probabilistic model \(g\) itself (threshold-free) and each derived classifier \(f_\tau\). We’ll resolve how at ch. 4 (evaluation metrics).

Qui apriamo il “punteggio interno” messo da parte al beat 2 (nota [:35]) e all’item 01. Esempi a voce: logistic regression, RF/NN col predict_proba. Da NON sbagliare: il task resta classificazione — apriamo il cofano, non contraddiciamo il beat 2.

Tre messaggi (i bullet a slide):

  1. Il modello fittato è \(g\); il classificatore nasce solo fissando \(\tau\).
  2. Un \(g\) → infinite \(f_\tau\): “valuto il classificatore” senza dire \(\tau\) è ambiguo.
  3. \(0.5\) = soglia di Bayes SOLO sotto \(0/1\) loss simmetrica → gancio al beat 5. Eco cap. 01 (95% accurate, clinically useless).

Se chiedono: \(K\) classi \(\to g:\mathbb{R}^d \to \Delta^{K-1}\) + argmax/soglie (solo a voce).

Gancio cap. 04: valutare \(g\) threshold-free (ranking/calibrazione, curva su TUTTE le \(\tau\)) vs un \(f_\tau\) (confusion matrix a quella soglia). Mantieni la promessa: NON nominare ROC/AUC.

Count the cost: risk = total loss.

Framing da insistere: il rischio è costo per gli sbagliati, non premio per i giusti. Lente cap. 01 (95% accurate, clinically useless).

0/1 loss and risk on a sample

0/1 loss — one unit of cost per misclassification:

\[\mathfrak{L}(y, \hat y) = \begin{cases} 1 & \text{if } y \ne \hat y \\ 0 & \text{otherwise.} \end{cases}\]

0/1 risk on a sample — the average loss over the \(n\) patients we have:

\[\widehat{\text{risk}}(f) \;=\; \frac{1}{n} \sum_{i=1}^n \mathfrak{L}\bigl(y_i, f(x_i)\bigr) \;=\; \frac{\#\text{misclassified}}{n}.\]

The lower-risk classifier is the better one on the data we have.

Da dire a voce: la risk-on-sample è solo stima della risk vera \(\mathbb{E}[\mathfrak{L}(f(X), Y)]\), ma è tutto ciò che possiamo calcolare. Distinguo “questo banco vs pazienti nuovi” → gancio finale + item 04 + cap. 04.

Slide bianca per fare i calcoli a mano: \(100+60=160<200 \Rightarrow 0\); \(140+70=210>200 \Rightarrow 1\); \(90+120=210>200 \Rightarrow 1\). Disegno alla lavagna la retta \(x+2y=200\) (passa per \((200,0)\) e \((0,100)\)), e marchio le due regioni.

Item 02 — Solution

1. Compute \(f\) for each patient.

  • P1 \((100, 30)\): \(\;100 + 60 = 160 < 200 \Rightarrow f = 0\) → low-risk.
  • P2 \((140, 35)\): \(\;140 + 70 = 210 > 200 \Rightarrow f = 1\) → high-risk.
  • P3 \((90, 60)\): \(\;90 + 120 = 210 > 200 \Rightarrow f = 1\) → high-risk.

2. Decision regions. The line \(x + 2y = 200\) passes through \((200, 0)\) and \((0, 100)\), splitting the plane into two half-planes: above-right $= $ high-risk (\(f=1\)); below-left \(=\) low-risk (\(f=0\)).

3. No gaps, no overlaps. \(f\) is a function: every \((x, y) \in \mathbb{R}^2\) goes to exactly one of \(\{0, 1\}\). The regions are the preimages \(f^{-1}(0), f^{-1}(1)\) — their union is the whole plane, their intersection is empty. Saying “\(f\) is a classifier” IS saying “the regions partition \(\mathbb{R}^2\)”.

Punto da far atterrare: partizione = definizione di “\(f\) è una funzione”, non scelta di disegno. Geometria = definizione.

Who draws the line — and how?

Nel cap. 02 il confine lo tracciava la mano di Elena. Ora lo traccia l’algoritmo. Tre famiglie principali, tre idee diverse di cosa sia una “linea sensata”.

Three families of algorithms

  • \(k\)-NN — the training data themselves define the boundary (lazy).
  • Linear / SVM — one global cut with the widest margin (and bend the space first if needed: the kernel trick).
  • Ensembles / Random Forest — many weak voters; the majority vote beats any single one (as long as each is better than chance).

Each family carries its own prior on what a sensible boundary looks like.

Cifra del capitolo (da landare a voce): a parità di dati, la forma di confine che ogni famiglia sa produrre è diversa — e quella forma, più del campione, decide cosa si vede.

\(k\)-NN: the data themselves decide.

A voce: \(k\)NN non fa regole, memorizza il training; copia la maggioranza dei \(k\) vicini. Il confine si incolla ai dati.

\(k\)-Nearest Neighbor — the recipe

For a new point \(x\):

  1. Find its \(k\) nearest training points (by some distance metric).
  2. Take a majority vote among their class labels.
  3. Assign that class to \(x\).

Rule of thumb in this chapter: \(k = 3\).

The decision regions are defined by the training points themselves — piecewise boundaries that hug each cluster’s edge.

  • A voce: niente parametri appresi, il training set è il modello (lazy learner).
  • \(k\) è un iperparametro: \(k\) piccolo → confine sinuoso (overfit, gancio cap. 04); \(k\) grande → smussato.

One straight cut. The shape is in the folds.

Analogia fisica del kernel trick. Lasciate la slide qualche secondo (riconoscono la stella di carta).

  • Teorema fold-and-cut (Demaine–Demaine–Lubiw, 1998): ogni poligono da un foglio con un solo taglio dritto, se piegato bene.
  • Punch line: il taglio è uno; è la piega che decide la forma. = classificatore fermo, cambia la rappresentazione.

A voce: dati non separabili → SVM non cambia algoritmo, cambia coordinate (la \(\phi\)). La linea torna a funzionare in alto, la riproietti come curva. Kernel trick = re-coordinatizzazione.

Linear SVM and the kernel trick

Linear SVM: find the widest-margin hyperplane between classes: \[f(x) = \text{sgn}(w^\top x + b), \quad x = (y_1, y_2).\]

When classes are not linearly separable, apply a feature map \(\phi:\mathbb{R}^d \to \mathbb{R}^D\) first: \[\phi(y_1, y_2) = \bigl(y_1^2,\; y_2^2,\; \sqrt{2}\,y_1 y_2\bigr).\]

Then cut with a hyperplane in the \(\phi\)-space; project back as a smooth curve in the original space. (For radially-symmetric data, \((y_1^2, y_2^2)\) alone suffices.)

The 2D data lifted into \(\phi\)-space, where a flat cut separates it.

The classifier did not change — what it sees did.

Take-away: kernel trick = cambio di rappresentazione, non nuovo algoritmo.

Aggancia all’item 02: cerchi concentrici → \((y_1, y_2) \mapsto (y_1^2, y_2^2)\) → separabili.

Many weak voters beat one strong.

A voce: tanti alberelli (\(p\) appena \(> 0.5\)) votano; il voto migliora con \(m\) solo se \(p > 0.5\).

Flag: il 3-column board (kNN · SVM · RF) è il perno del sommativo.

Random Forest and the majority vote

Random Forest = many small decision trees, each trained on a bootstrapped slice of the data, combined by majority vote.

For \(m\) independent weak classifiers each with per-classifier accuracy \(p\):

  • if \(p > 0.5\) → vote accuracy goes up toward \(1\) as \(m\) grows;
  • if \(p < 0.5\) → vote accuracy goes down toward \(0\) as \(m\) grows.

Voting amplifies whichever direction \(p\) points. Hence the \(p > 0.5\) requirement.

(Real forests only approximate independence — bootstrapping \(+\) random feature subsets de-correlate the trees; the clean “\(\to 1\)” is the idealisation.)

Punto quantitativo: voto di maggioranza ≠ media — è una binomial tail che si concentra al crescere di \(m\). L’item 03 testa la direzione.

Correct: A. The majority-vote accuracy concentrates as \(m\) grows:

  • if \(p > 0.5\) → vote accuracy goes up toward \(1\);

What does training error actually measure?

Training error = how well the model fits the data it was trained on.

It does not tell us how the model will do on patients we have not measured.

The more flexible the model, the better it can fit any specific training set — at the cost of fitting that one set rather than the underlying pattern.

Overfitting concettuale prima di nominarlo. Gancio cap. 02 item 04 (“but on a different group of patients?”): stessa domanda, oggi la chiudiamo.

Training error falls. New-data error eventually rises.

Punto chiave: la U. Train scende verso zero; new-data scende, minimo, poi risale; il gap si allarga oltre il minimo. Overfitting = impara il campione, non il segnale.

Overfitting — the signature

A model is overfitting when:

  • its training error is low (it has memorised the training sample), and
  • its error on new data is much higher (the gap is large).

It has captured idiosyncrasies of the sample, not the underlying signal.

The opposite failure — underfitting — is when both errors are high: the model is too rigid to capture even the training data.

Insisti sulla diagnosi differenziale: overfit = basso train + grande gap; underfit = entrambi alti e vicini. Item 01 testa proprio questo.

Aside — Which error? A quick metric tour

For a binary classifier, the confusion matrix counts four outcomes:

predicted \(+\) predicted \(-\)
actual \(+\) TP FN
actual \(-\) FP TN

From it, the most-used metrics:

  • Accuracy \(= \dfrac{TP + TN}{TP + TN + FP + FN}\) — overall correct rate.
  • Balanced accuracy \(= \dfrac{1}{2}\!\left(\dfrac{TP}{TP + FN} + \dfrac{TN}{TN + FP}\right)\) — avoids the majority-class trap on imbalanced data.
  • Sensitivity (recall, TPR) \(= \dfrac{TP}{TP + FN}\) — of the actual positives, how many caught.
  • Specificity (TNR) \(= \dfrac{TN}{TN + FP}\) — of the actual negatives, how many spared.
  • Precision (PPV) \(= \dfrac{TP}{TP + FP}\) — of those flagged positive, how many really are.

Aside metriche — ~60-90″, non valutata.

  • a voce: malattia rara al \(5\%\), “sempre sano” → accuracy \(95\%\) ma sensitivity \(0\). Balanced accuracy neutralizza il bias di prevalenza.
  • sinonimi: sensitivity ↔︎ recall; precision ↔︎ PPV (clinico vs ML).
  • gancio: tutte presuppongono una soglia fissa — slide dopo la togliamo.

Aside — Threshold-free: AUC-ROC vs AUC-PR

Most classifiers output a score \(g\) (often a probability — ch. 2’s \(g\)); the threshold \(\tau\) turns it into a label \(f_\tau\). Sweeping the threshold traces two curves:

  • ROC curve — sensitivity vs \(1 - \text{specificity}\) across thresholds. Its area, AUC-ROC \(\in [0, 1]\) (\(0.5 =\) random, \(1 =\) perfect), is the probability that a random positive scores higher than a random negative.
  • PR curve — precision vs recall. Its area, AUC-PR, is more informative when the positive class is rare (its baseline is the prevalence, not \(0.5\)).

Rule of thumb: AUC-ROC when classes are roughly balanced; AUC-PR under heavy imbalance (rare disease, fraud, anomaly detection).

Threshold-free — ~60-90″. Idea: buona metrica = non dipende da una soglia, riassume tutte.

  • a voce: AUC-PR baseline = prevalenza (non \(0.5\)); ROC può sembrare alta (\(0.85\)+) con pochi veri positivi tra molti falsi → screening malattie rare, usa AUC-PR.
  • nominale e basta; dettagli in index-full.Rmd.

Every decision spends data.

Regola del capitolo: contamination principle. Ogni numero usato per scegliere è speso, non è più stima onesta. Per questo il test sta dietro vetro fino a scelta fatta.

The contamination principle

Every time you take a decision based on a number from a dataset, that number is no longer a valid estimate.

Concretely:

  • Use validation error to choose between models → that validation error is spent as a future estimate.
  • Use test error to choose (even just to pick a winner among candidates) → the test set is spent.

The only honest number is one that was not used to decide anything.

Lente che unifica train/val/test. Lo studente sa che serve un test; la sottigliezza è il perché: ogni decisione costa un numero.

  • frase da incidere: “every decision after looking at a number contaminates that number as a future estimate”.
  • vocabolario richiamato al sommativo.

Three sets, one job each — and the test stays untouched.

Tre set: train fitta, validation (\(K\)-fold CV) sceglie, test conferma. Perno del capitolo: anticipa la tabella a 4 righe del sommativo (\(M_A\)–\(M_D\), train vs CV).

Train / Validation / Test — one role each

Subset Role Used to
Training fit learn the model’s parameters
Validation choose compare candidate models / hyperparameter settings
Test confirm estimate final performance on truly unseen data

The same data cannot play two roles. Choosing a model on a set spends that set’s number as a future estimate.

A voce il perché tre e non due: fittare + scegliere (consuma il set) + un set intatto per stimare. Richiama la contamination rule del beat prima.

\(K\)-fold cross-validation — the recipe

The validation step, done practically:

  1. Split the (non-test) data into \(K\) equal blocks.
  2. For \(k = 1, \ldots, K\): train on the other \(K - 1\) blocks; estimate error on block \(k\).
  3. Average the \(K\) per-fold error rates → the CV error.

Standard \(K \in [5, 10]\): smaller \(K\) → each fit sees a smaller fraction of the data (high bias); larger \(K\) → smaller folds (high variance).

The CV error estimates the prediction error of the chosen model on unseen patients.

Procedura canonica del validation. Dopo la scelta col CV quel numero è speso → pushback item 03 + sommativo. La regola sui \(K\) è bias-variance dei fold: voce docente, non valutato.

Aside — What did the model learn? Global importance (VIMP)

After validating that a model predicts well, a second question follows: which features is it relying on?

Variable importance — permutation-based (VIMP):

  1. Measure the validated model’s error \(E\).
  2. Permute the values of feature \(X_j\) across patients — this breaks any signal in \(X_j\), keeping everything else fixed.
  3. Re-measure the error \(E_j\). The importance of \(X_j\) is \(E_j - E\): how much performance drops when \(X_j\) is scrambled.

Born with random forests, but works for any fitted model (model-agnostic).

VIMP — ~60″. Idea: permuti \(X_j\), se l’errore non cambia non contribuisce. Globale: una classifica per l’intero dataset.

  • caveat a voce: NON è causalità — può pescare confondenti (es. “ICU room number” proxy di gravità).
  • predittori correlati: l’importanza si “spalma”, sottostima entrambi.
  • vendila come sanity check post-fit, non spiegazione causale.

Aside — Why this prediction? Local explanations (SHAP)

VIMP tells you which features matter on average. SHAP tells you how each feature contributed to a single patient’s prediction.

  • Borrowed from cooperative game theory (Shapley values, 1953): each feature is a “player”; its SHAP value is its fair share of the prediction’s deviation from the average — like splitting a bill by what each guest actually ordered.
  • For one patient: a positive SHAP value pushes the prediction up; a negative one pushes it down. Contributions are additive.
  • Aggregated across patients, SHAP also yields a global view that is consistent with the local explanations.

Model-agnostic; standard tooling for tree ensembles today — and the deep nets and LLMs of later chapters.

SHAP — ~60″. Idea: scomposizione additiva per-paziente → “why was THIS patient flagged?”.

  • onestà: spiega il modello, non la biologia (come combina le feature, non perché la malattia esista).
  • take-home: VIMP globale + SHAP locale = i due bisogni clinici.
  • gancio cap. 05: nei deep net SHAP resta utile ma più costoso.

Item 04 — Solution

1. Flaw at Steps 4–5. The test set has been used to choose among the three retrained techniques. Picking the technique with the lowest test error among three is a decision based on test-set numbers — the contamination principle rules it out. The reported test error of the winner \(M_\star\) is no longer unbiased: it is the minimum of three test errors, optimistically biased. Each technique’s within-technique CV tuning at Step 2 was correct, but a second selection step has been hidden inside Steps 4–5, turning the test set into a between-technique validation set.

2. Correct procedure. Do all selection at the validation step — both within and between techniques:

  • For each technique, CV-tune its hyperparameters on train+val.
  • Use the same CV to compare the 3 tuned candidates and pick a single \(M_\star\) (the technique-and-setting with lowest CV error overall).
  • Retrain only \(M_\star\) on train+val combined.
  • Evaluate \(M_\star\) once on the held-out test set; report.

The artificial neuron

Given inputs \(a = (a_1, \ldots, a_n)\) and weights \(w = (w_1, \ldots, w_n)\):

\[\text{out} = g\!\left(\sum_{i=1}^{n} a_i \, w_i\right)\]

The chapter 2 logistic regression is the special case \(g = \sigma\) (sigmoid). The artificial neuron frees \(g\) — any non-linear and differentiable function will do.

Struttura somma pesata + attivazione = la logistica di ch. 02, ma \(g\) libera (non solo \(\sigma\)).

  • Vocabolario: non-lineare = forma di \(g\) (non delle feature); differenziabile = serve al training (slide dopo).

Activation functions \(g\) — common choices

The chapter requires \(g\) to be non-linear and differentiable (almost everywhere). Three canonical choices:

  • ReLU (Rectified Linear Unit): \(g(z) = \max(0, z)\) — the field’s workhorse since the 2010s.
  • Sigmoid: \(g(z) = \sigma(z) = \dfrac{1}{1 + e^{-z}}\) — the same one from chapter 2 logistic regression.
  • Hyperbolic tangent: \(g(z) = \tanh(z) = \dfrac{e^z - e^{-z}}{e^z + e^{-z}}\).

All three satisfy the two requirements (ReLU is differentiable almost everywhere — the single point \(z = 0\) is handled in practice with the sub-gradient \(0\)).

A voce (non sulla slide): ReLU = default hidden (cheap); sigmoid = output binario (prob.); tanh = sigmoid centrato in \([-1,+1]\).

  • Anti-trabocchetto: ReLU non differenziabile in \(z=0\), ma OK col sub-gradient \(0\).
  • ReLU è la canonical di item 02 e 03.

Composition — a fully-connected (MLP) network

Stack neurons into layers; feed the outputs of one layer as the inputs of the next:

\[a^{[l]} = g^{[l]}\!\left(W^{[l]} \, a^{[l-1]}\right)\]

where \(W^{[l]}\) is the weight matrix of layer \(l\).

A toy network \(3 \to 2 \to 2 \to 1\) (no biases) has:

\[\underbrace{3 \cdot 2}_{\text{layer 1}} + \underbrace{2 \cdot 2}_{\text{layer 2}} + \underbrace{2 \cdot 1}_{\text{layer 3}} = \mathbf{12}\ \text{weights}.\]

Twelve. Drawable on a napkin. (The badge says 17 — that’s the \(12\) weights \(+\) \(5\) biases; here we count weights.)

Punto di svolta. Da landare: rete profonda = composizione di oggetti familiari, non nuovo oggetto matematico.

  • \(10^6\) pesi = stesso ragionamento con più righe, non fenomeno diverso.

Weights are coordinates. Loss is the height. Walk downhill.

Il come impara. Tripla metafora da insistere a voce: pesi = coordinate, errore = altezza, training = camminare in discesa.

Gradient descent — the training loop

For a given training set, each combination of weights \(W\) has a loss \(L(W)\) — the empirical risk of ch. 2, now read as a function of \(W\):

  • \(W\) = coordinates in \(\mathbb{R}^d\) (where \(d\) = number of weights).
  • \(L(W)\) = the height of the loss surface at \(W\).

Gradient descent: walk downhill, one small step at a time:

\[W \leftarrow W - \eta \, \nabla_W L(W).\]

  • \(\nabla_W L(W)\) = direction of steepest ascent; we go against it.
  • \(\eta\) = learning rate = how big a step we take.

Sign (\(-\)) = scendi/sali; \(\eta\) = lunghezza passo. Item 03 testa la coppia (distrattori sign × \(\eta\)).

  • A voce: backprop = come si calcola \(\nabla_W L\) (chain rule per strato), ma NON da derivare a mano in questo corso.

Why must \(g\) be non-linear and differentiable?

Both requirements have operational meaning for the training procedure:

  • Non-linear \(g\) → the stack of layers is more than one big linear map. Were each \(g\) linear, the whole stack would collapse to \((W^{[3]} W^{[2]} W^{[1]})\,x = W x\) — one matrix multiplication, no matter how many layers. No “deep”.
  • Differentiable \(g\) → the gradient \(\nabla_W L(W)\) exists at every \(W\). Otherwise: no direction to step in, and gradient descent has nothing to do. No “learning”.

The two together: a curved loss landscape with a slope at every point. That’s what makes descent possible.

Payoff Obj. 3: non-linearità → terreno curvo; differenziabilità → pendenza ovunque. Formulazione da portare fuori dall’aula.

  • A voce (non sulla slide): perceptron anni ’60 usava step di Heaviside → non differenziabile, training impossibile; servì il 1986 (Rumelhart-Hinton-Williams) con attivazioni smooth. È la lezione storica del DL.

Fully-connected on a chest X-ray — back of the envelope

CNN — share across space

A small kernel \(K \in \mathbb{R}^{k \times k}\) (typically \(3 \times 3\) → \(9\) weights) is slid across the input image. At every position \((i, j)\):

\[F_{ij} = g\!\left(\sum_{u=1}^{k}\sum_{v=1}^{k} K_{uv}\, X_{i+u-1,\, j+v-1}\right).\]

The same \(K\) at every position.

Two operational consequences:

  • Weight count: \(9\) weights for the whole layer, independent of image size — vs \(\sim 10^{4}\)–\(10^{6}\) for a fully-connected layer on the same input.

  • Translation equivariance: the kernel that learned to detect an edge detects it wherever it appears (true invariance follows after pooling) — the geometric prior is encoded in the architecture, not learned from data.

  • Insisti: stesso kernel a ogni \((i,j)\), non uno per pixel.
  • Frase-chiave: la CNN è un MLP con vincoli sui pesi — togli i vincoli, torna l’MLP.
  • Fuori scope (dillo se chiedono): stride, padding, max-pooling, RGB.

CNN — typical deep stack

A real CNN stacks many kernels (one per feature), in many layers — but each kernel is small and shared across space. The total parameter count stays modest even when the network is “deep”.

Slide-vetrina (idea già data prima). Di’ a voce: gli ingegneri ML giocano sui kernel/strato (8 → 16 → 32 → …), lì sta l’arte, non l’idea. La cifra resta: ogni kernel è shared across space.

RNN — share across time

At every position \(t = 1, \ldots, T_x\):

\[a^{<t>} = g\!\left(W_{aa}\, a^{<t-1>} + W_{ax}\, x^{<t>} + b_a\right)\]

\[y^{<t>} = g'\!\left(W_{ya}\, a^{<t>} + b_y\right)\]

The same matrices \(W_{aa}, W_{ax}, W_{ya}\) at every position \(t\).

Two operational consequences:

  • Parameter count is independent of \(T_x\) — the same \(W\) matrices process a \(5\,000\)-sample ECG and a \(5 \times 10^{5}\)-sample one.

  • Memory — because \(a^{<t>}\) depends on \(a^{<t-1>}\), the hidden state at \(t\) carries, in principle, the network’s record of everything it has read so far.

Stesso trucco (weight sharing), asse tempo. Le tre matrici \(W_{aa}, W_{ax}, W_{ya}\) = i tre nomi per sommativo + item 03.

  • Fuori scope (se chiedono): LSTM/GRU, vanishing gradient, bidirectional.

RNN — every position needs every previous one

The RNN of ch. 6 propagates the dependency through the recurrence

\[a^{<t>} = g\!\left(W_{aa}\, a^{<t-1>} + W_{ax}\, x^{<t>} + b_a\right) \qquad \text{for } t = 1, \ldots, T_x.\]

Position \(t\) cannot be computed until \(t-1\) has been computed — the loop is serial. The trace of denies must travel through every intermediate word until it reaches contradicts: \(T_x - 1\) occasions to fade, and zero parallelism on the GPU.

Bottleneck doppio: (i) fade del segnale; (ii) non-parallelizzabilità (\(t \leftarrow t-1\) è seriale anche su GPU). Frase da landare: “non era solo lento — era non-parallelizzabile”.

Self-attention — the formula in one line

Each token is projected into three vectors — a query \(Q\), a key \(K\), a value \(V\). Self-attention computes

\[\text{attention}(Q, K, V) \;=\; \text{softmax}\!\left(\dfrac{Q K^{\top}}{\sqrt{d_k}}\right) V.\]

  • \(Q K^{\top}\) is a \(T_x \times T_x\) table of all pairs of positions at once.
  • The softmax normalises each row into weights.
  • \(V\) recombines the tokens by those weights.
  • The dependency between position \(1\) and position \(T_x\) is one entry \((Q K^{\top})_{T_x,\,1}\) — one operation away.

La formula va presentata e usata, non derivata. \(Q K^{\top}\) = single matmul parallela su GPU → ragione strutturale del sorpasso sulla RNN.

  • Soundbite che lo studente deve saper dire: “every token sees every other, in parallel, weighted by softmax of \(Q K^{\top}\)”.
  • Fuori scope (non valutato): multi-head, positional encoding, RoPE, layer norm, residual.

The \(2 \times 2\) trust boundary

Reversible (\(Y\)) Irreversible (\(N\))
Human-in-the-loop (\(Y\)) \(\text{SAFE}\) — read \(+\) undoable \(\text{SAFE}\) — pre-action read (the gate)
No human-in-the-loop (\(N\)) \(\text{SAFE}\) — undoable \(\textbf{DANGEROUS}\) — no read, no undo

Reversibility test. Can the action be undone in \(\sim 30\) seconds by closing a tab, deleting a file, or rolling back a draft? Yes \(\Rightarrow\) reversible.

HITL test. Did a human read the agent’s reasoning before the action happened? After is post-mortem; before is a gate.

The rule, one sentence:

A step is safe by default if it is reversible or human-in-the-loop. It is dangerous by default only when it is neither.

The rule reads disjunctively (OR), not conjunctively (AND). Three of the four cells of the \(2 \times 2\) grid are safe; only one is dangerous.

Earn complexity — write the rule before training

The first three lines of the planning document — written before any model is trained.

  1. Baseline — the simplest model on the smallest sensible feature set. E.g. logistic regression on \(5\)–\(10\) clinically-chosen features (age, ICU LOS, Charlson, prior \(90\)-day admissions, eGFR at discharge, number of medications).
  2. Baseline metric \(+\) target — a number the baseline could plausibly reach. E.g. AUPRC (ch. 4’s AUC-PR) \(\ge 0.30\) on the held-out validation split (or recall \(\ge 0.60\) at precision \(\ge 0.30\)).
  3. Escalation rule — one named failure, one named direction, one named “ship the baseline” branch. E.g. “if the baseline reaches the target on validation, ship the baseline; otherwise escalate to gradient boosting on a wider clinical feature set.”

Why the rule must be written ex ante.

Written before the run, the rule constrains the run. Written after, it is a rationalisation of decisions already made — and the ethics committee will read it as such.

A binding stop-criterion has two real branches: escalate and ship the baseline. If the target is rigged so high that only escalate can ever fire, the rule has collapsed into a plan disguised as a rule.

More parameters and richer features are paid for in robustness, interpretability, and risk of overfitting — so each added unit of complexity must be earned by a failure of the simpler model.

Protect the test — two rules, one discipline

R\(1\) — accuracy trap.

On a prevalence \(p\), the always-predict-majority classifier reaches accuracy \(1 - p\) with \(0\) recall on the rare class. On \(p = 5\%\) that is \(\boldsymbol{95\%}\) — statistically brilliant, clinically useless.

  • discard accuracy on imbalanced data;
  • choose AUPRC, F\(1\), or recall at a target precision;
  • set the threshold on the clinical cost ratio of FP vs FN, not on a curve in isolation.

The relevant baseline on imbalanced data is always-predict-NO, not a coin-flip.

R\(2\) — leakage rule (ch. 4’s contamination principle, sharpened).

Any decision (model, hyperparameter, feature set, threshold) taken after having seen a performance number on a dataset converts that dataset into a training set — even if the file is labelled “test”.

The test is looked at exactly once, at the end, and never again.

  • the trigger is the decision, not the observation;
  • contamination is retrospective — no procedure applied afterwards repairs the original test;
  • the fix for a contaminated test is a new held-out split, not a fresh validation.

A fresh validation split is where thresholding and tuning live; the test stays in the drawer.

The clinical-defensibility rule, one sentence:

If the deployment requires clinical defensibility, prefer a model whose interpretability is built-in — unless the performance gap to the opaque model is large enough that the patient is better off with the box-with-attribution than with a simpler model that misclassifies more often. The tradeoff is a clinical decision, not a technical one.

The committee’s question is not “is the model interpretable?” — it is “why this model on this patient?”. The answer is owed to the patient, before the committee even asks.

Item 01 — Question

Marco is about to start an audit on \(30\)-day ICU readmission (\(5\,000\) patients · \(50\) features · \(p \approx 5\%\) · defence in three weeks). He shows you four versions of the Methods — four ways of writing the stop-criterion that earn complexity asks for. Which one applies the discipline correctly?

  • A) Marco trains logistic regression on \(6\) features (validation AUPRC \(0.27\)), then gradient boosting on the same features (validation AUPRC \(0.31\)). With both results in front of him he writes: “We adopted gradient boosting because logistic regression failed to reach the AUPRC target we had set for the baseline.”
  • B) Before training: “We will train gradient boosting on \(30\) features as our primary model — gradient boosting consistently outperforms logistic regression on tabular clinical data. We will report AUPRC and recall on the test set. If unsatisfactory, we will revisit the modelling choice.”
  • C) Before training: “Baseline: logistic regression on \(6\) clinically-chosen features. Target: AUPRC \(\ge 0.30\) on validation. Escalation: if the baseline does not reach AUPRC \(0.30\) on validation, escalate to gradient boosting on a wider feature set; if the baseline reaches the target, ship the baseline.”
  • D) Before training: “Baseline: logistic regression on \(6\) features. Target: AUPRC \(\ge 0.80\) on validation. Escalation: if the baseline does not reach \(0.80\), escalate to gradient boosting.”

Item \(01\) — Comprehension / MCQ / medium. Obj. \(1\). A è il distrattore più comune (timing wrong — Methods scritto dopo); D è il più sottile (timing right, struttura right, target rigged — l’if-then ha solo un ramo reale). Lascio \(1\)–\(2\) minuti.

Item 01 — Solution

Correct: C. Only C carries all three components of earn complexity, each correctly placed in time: (i) timing — ex ante (the rule is written before the run, so it can constrain the run); (ii) baseline — simplest model on smallest sensible feature set (logistic regression on \(6\) clinically-motivated features); (iii) target — realistic given the prevalence (AUPRC \(\ge 0.30\) at \(p = 5\%\) is reachable by a \(6\)-feature logistic, so the not-escalate branch has a real chance of firing).

  • A — wrong on timing. Methods is written after both runs; the rule did not govern the work, it described it. The most common failure mode in published clinical-ML papers.
  • B — wrong on the baseline. Gradient boosting on \(30\) features as primary model — no simpler baseline, no documented failure of the simpler model to earn the complexity. The committee’s “why this model?” cannot be answered with population-level priors.
  • D — wrong on the target. AUPRC \(\ge 0.80\) on \(p = 5\%\) is roughly twice the realistic ceiling for \(30\)-day ICU readmission (historical range \(0.20\)–\(0.45\)) — the if-then has only one real branch (escalate). A stop-criterion with only one real branch is a plan disguised as a rule.

Discriminator: a binding stop-criterion is temporally ex ante \(\wedge\) starts simple \(\wedge\) has a real not-escalate branch.

Take-home: earn complexity = temporale + strutturale + realistico.

Correct: B. Only B names the right baseline (always-predict-NO, accuracy \(1 - p = 95\%\)), the right discriminator (recall on the positive class / AUPRC — both immune to majority-prediction inflation), and the right operational anchor (recall at the threshold the clinician would use).

A = legge R\(2\) come “non training-on”, non come “no-decision-after-observation”; C = trasparenza \(\ne\) correttezza; D è il più sottile — operationally right direction (fresh validation è la fix per il futuro), ma il test originale è già contaminato — serve un new test, non solo una fresh validation. Item 03 — Solution

Correct: B. Three components of R\(2\) carry the answer:

  • The rule triggers on the decision, not on the observation. Step \(4\) alone (a single read with no decision) leaves the test faithful. Step \(5\) is the trigger — because of \(0.29\), Davide changes the model; that decision uses test information to shape the model.

  • Contamination is retrospective, not prospective. Once R\(2\) is violated, the original test is no longer a test split — no procedure applied afterwards restores it. The number \(0.31\) is read off an already-contaminated split.

  • The fix is a new held-out split. A fresh validation split fixes future tuning; it does not repair the already-contaminated test. The chapter’s exact wording: the test is “looked at exactly once, at the end, and never again” — a split looked at twice can never be that split again.

  • A — textbook-mechanical reading of “test set” = “data not fit on”. R\(2\) is operational: test information leaks via decisions taken on test numbers, not only via gradient updates.

  • C — transparency ≠ correctness. A disclosed biased number is still a biased number.

  • D — operational direction right (praise this at the reveal), rule wrong. The contaminated test cannot be legitimised by a procedure applied later; only replaced. Fresh validation fixes tomorrow; a new test is what answers today.

Discriminator: read R\(2\) as a rule about decisions on a dataset, applied retrospectively to the moment of the decision.

Take-home: R2 non è “non fit on test” — è “nessuna decisione dopo un’osservazione sul test”.

Item 04 — Solution (Excellent-level response)

(a) We will use variable importance computed across the random forest ensemble — a ranking of features by their average contribution to separating readmitted from non-readmitted patients. Variable importance matches the random forest family because the model’s prediction is the average across many independent trees: no single tree’s coefficient or rule is the model, so there is no per-feature weight with sign and magnitude to read off — the built-in route is unavailable, and a post-hoc ranking stands in for it. For the committee’s “what does the model rely on?” we report the global ranking; for the clinical lead’s “why this patient?” we additionally show the top-ranked features against that patient’s chart, so the explanation lands on the record the clinician is already reading.

(b) The random forest catches meaningfully more readmissions than the logistic baseline (\(0.32\) vs \(0.27\) AUPRC, an extra recall margin clinically material on this service) — and the clinical cost of a missed \(30\)-day readmission (re-admission, possible adverse event, longer LOS) substantially exceeds the cost of explaining each prediction with a feature-importance ranking rather than a logistic coefficient, so on this audit the patient is better served by the more accurate model with a variable-importance defence than by the simpler logistic that misses more events.

Item 04 — Solution: what the rubric rewards

Three rubric criteria (\(3\) levels each: Base / Good / Excellent).

  • C\(1\) — Technique matching. Variable importance for RF; rules out coefficients. Excellent: distinguishes global (committee) from per-patient (clinical lead) and names a concrete per-patient route (top-ranked features against the chart, or SHAP as bonus if anchored).
  • C\(2\) — Technical justification. Built-in (linear → coefficients, single tree → decision path) vs post-hoc (RF/GB → variable importance, NN → SHAP/surrogate) as a \(1{:}1\) rule, not a menu.
  • C\(3\) — Clinical defensibility. The subject is the patient, the cost-of-failure is clinically named, the tradeoff is posed and resolved by the clinical lead’s cost ratio.

The inverted answer — revert to logistic + coefficients — is accepted at Excellent if matching is correct AND the clinical argument is well-posed (“on this audit the extra recall does not justify the loss of built-in interpretability, given our cost ratio”).

The rubric measures applying the tradeoff as a clinical decision, not picking random forest.

Bias to avoid: penalising a logistic-baseline answer as a retreat — it is the winning case of the discipline when the baseline reaches the target.

Item 05 — Solution (c): the corrected plan

Before any training, write the stop-criterion: baseline \(=\) logistic regression on \(5\)–\(10\) clinically-chosen features (e.g. age, ICU LOS, Charlson, prior \(90\)-day admissions, eGFR, \(\#\) medications); target \(=\) AUPRC \(\ge 0.30\) (or recall \(\ge 0.55\) at precision \(\ge 0.40\)) on a held-out validation split; escalation \(=\) if the baseline misses the target, escalate to random forest on a wider clinical feature set; otherwise ship the baseline.

The metric is not accuracy — AUPRC or recall-at-precision, because \(5\%\) prevalence makes accuracy uninterpretable; the threshold is set by the cost ratio the clinical lead signs off on, not by an arbitrary \(90\%\).

Hyperparameter tuning runs on a fresh validation split drawn from the training pool; the test set is sealed in a separate folder until the day of the defence and opened exactly once, on that day.

Interpretability matches whatever model finally ships: coefficients if the logistic baseline reaches the target (which on this audit is the most defensible outcome — built-in interpretability, simpler model, smaller per-patient risk per unit error); variable importance \(+\) top-ranked features against this patient’s chart if escalation is required, with the tradeoff posed explicitly to the clinical lead.

The plan does not predetermine the model; it predetermines the discipline that decides between models. The three disciplines compose — start simple, measure honestly, defend clinically — as an order of operations, not as four independent patches.
