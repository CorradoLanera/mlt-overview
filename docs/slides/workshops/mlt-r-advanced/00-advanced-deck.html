Open the model you validated in Basic

Voce docente (IT): apertura. L’arco RIAPRE il modello validato in Basic — non si ricostruisce nulla. Quattro tappe: interpretare (VIMP/SHAP) → deep learning (torch/ luz/brulee) → ellmer come ETL tipizzato → capstone targets. torch è pre-riscaldato nello step 00 (torch_tensor(1)), così il primo tensore non paga l’init. Numeri reali da ricordare: l’RF di Basic sta a CV AUC-ROC ~0.79; VIMP mette in cima ejection_fraction / serum_creatinine. NON vendere l’MLP come vincitore della foresta.

The model you built in Basic is not the end — it is the subject. We open the random forest you built and validated in Basic, then push past it.

  • Interpret it — permutation VIMP and agnostic SHAP, anchored on a logistic regression.
  • Go deep — a live brulee MLP (torch / luz / brulee), then CNN/RNN/fused nets written (not trained).
  • Reach an LLM — ellmer as a typed, reproducible LLM-as-ETL.
  • Seal it — a targets pipeline that re-derives the explanation, all-skip on re-run.

Everything live-coded; nothing pre-baked is shown as live (one labeled exception).

Step 01 · Interpretability

Objectives. Open the black box with two model-agnostic tools.

  • Permutation VIMP ({vip}): shuffle a predictor \(\to\) how far AUC-ROC drops = how much the model relies on it. Reliance, not causation.
  • Agnostic SHAP via kernelshap + shapviz: attribute one prediction across features.
  • The same explainer line runs on logistic \(\to\) RF \(\to\) MLP — only the model object changes.

Voce docente (IT): hands-on (~48 min), zona di rischio per profondità. Min-24 (MCQ): VIMP = reliance, NON causazione / coefficiente con segno / p-value. Numero reale di build: la VIMP a permutazione mette in cima ejection_fraction e serum_creatinine (con age) — i predittori clinicamente sensati, con effetti soglia/non-monotoni. Sono le feature che la foresta ha imparato a USARE, non un’affermazione causale né di direzione.

The logistic anchor — SHAP must recover what we already know

Before pointing SHAP at the opaque forest, we anchor it on a logistic regression — a model we can read off its coefficients.

  • Run SHAP on the linear anchor with permshap() (near-exact Shapley values).
  • The SHAP attributions must echo the fitted coefficients — same leading features, consistent signs. If they did not, we would not trust SHAP on the forest.
  • Build reality: ejection_fraction, age, serum_creatinine lead both the waterfall and the largest-magnitude coefficients.

Then the agnosticism payoff: the same call points at the random forest (no coefficients at all) — kernelshap() for the forest, permshap() reserved for the linear anchor.

Voce docente (IT): predict-output al min-38 — che forma ha lo SHAP rispetto ai coefficienti logistici? Perché rassicura PRIMA di puntare l’RF: l’agnostico deve recuperare il noto. permshap() = esatto sul lineare (il sanity-check più pulito); kernelshap() = ibrido sull’RF (11 feature, scelta pratica). “Your turn” min-66: la stessa riga del blocco 01 puntata sull’RF — cambia solo l’oggetto-modello.

SHAP settings — variance vs. cost

Three settings govern an agnostic SHAP run. None of them is a quality dial.

setting what it is the tradeoff
background (bg_X) reference rows SHAP integrates over larger \(\to\) lower-variance attributions, higher cost; tiny \(\to\) cheap but noisier
which rows (X) the patients you explain a waterfall explains one row; pick the case(s) you actually care about
exact vs. sampling how Shapley values are computed permshap() exact for small \(p\) / the linear anchor; kernelshap() hybrid/sampling as \(p\) (the number of features) grows
  • Smaller background is not “more accurate” — it is cheaper and noisier.
  • With 11 features the exact enumeration gets expensive \(\to\) the forest uses the hybrid kernelshap().

Voce docente (IT): min-46 (MCQ). Sostituisce il vecchio framing “nsim” — ora si usa kernelshap (override 2026-05-31, §11). Lezione invariata: varianza-vs-costo. Distrattori adattati: “meno background = più accurato” (NO, più rumoroso), “background conta solo per alberi” (NO, è agnostico), “X = numero di feature” (NO, sono le righe da spiegare). permshap esatto sull’ancora lineare, kernelshap ibrido come p cresce.

MLP hyperparameters — and the overfit cure

A small brulee MLP has four primary hyperparameters (plus two minor). With generous defaults a small net overfits this 299-patient cohort — and the cure is always the same.

hyperparameter what it controls bias / variance
epochs how long it trains too many \(\to\) fits noise (overfit)
learn_rate step size of each update too high \(\to\) diverges; too low \(\to\) underfits in budget
hidden_units capacity (width) more \(\to\) lower bias, higher variance
penalty weight decay (regularization) \(\uparrow\) penalty \(\to\) more bias, less variance
  • Minor settings: batch (gradient noise) and activation (nonlinearity) — not regularizers.
  • Overfit cure: turn penalty up and hidden_units down (or cut epochs).

Voce docente (IT): min-60 (MCQ). MLP overfit → quale knob? ✓ penalty↑ / hidden↓. Distrattori: “più epoche” (peggiora), “learning-rate↑” (diverge), “cambia activation come regolarizzatore” (NO, l’activation non regolarizza). Fallo dal vivo cambiando UN solo numero. La slide-parametro viene PRIMA del train (knob pre-caricati).

CNN / RNN / fused — written, not trained

Three richer nn_modules, written not trained — validated only by a forward() shape-check.

net the hyperparameters shape role
1D-CNN kernel / stride / channels slides a filter over a signal
RNN hidden / sequence / LSTM-GRU reads a vitals sequence over time
fused 3 branches \(\to\) torch_cat(dim = 2) \(\to\) head branch widths must sum to the head input
  • The fused net runs all three branches and concatenates them along dim = 2 into a two-logit head.
  • A correct [5, 2] out (five patients, two logits) proves the wiring — it claims nothing about accuracy.

Voce docente (IT): min-80 (Parsons). Riordina il forward() della rete fusa: 3 rami → torch_cat(list(t, c, r), dim = 2) → head. Vincolo fisso: prima calcoli i rami, POI concat-e-head; la larghezza d’ingresso della head = somma delle larghezze dei 3 rami. Lo split scrivi-non-addestra collassa CNN+RNN+fused in UN solo schema (“modulo cablato dal forward”) → da 9 a ~5 chunk effettivi. Nessun training: solo [5,2].

The honesty rule — one labeled exception

Everything on screen is either live or declared write-only. The doctrine is explicit.

  • The MLP above is trained live; its roc_auc is a genuine held-out number.
  • The CNN/RNN/fused nets are shape-checked write-only — never presented as trained.
  • The GPU demo’s killed CPU epoch was live — a real interrupted epoch, not a simulation.

The one labeled exception. The fused-net loss curve is pre-computed — “I trained this earlier on GPU.” It is labeled in the plot title and is the only pre-baked result.

targets is not an exception. A cached target re-shown as “skip” is reproducibility (re-derivable, hash-checked: same input \(\Rightarrow\) same output), not fakery — conceptually the opposite of a pre-baked number shown as live.

Distrattori: “nessuna cache mai” (NO), “tutto DL pre-trainabile senza label” (NO), “identico al cache di targets” (NO — la riproducibilità hash-checked è un’altra cosa). GPU payoff — where the accelerator actually pays

The accelerator is not a magic speed button. Match it to the workload.

  • The tiny tabular MLP does not need a GPU — it trains in seconds on a CPU (overhead would lose).
  • The payoff is on the CNN / fused workload, where the per-epoch cost actually bites.
  • The live classroom move: start on CPU \(\to\) watch one epoch crawl \(\to\) kill it \(\to\) rerun on GPU.
  • Authored write-only (#| eval: false): it runs on the classroom NVIDIA/CUDA machine, where cuda_is_available() is TRUE — not on this CPU build box (FALSE).

Voce docente (IT): non vendere la GPU sul giocattolo (MLP minuscolo), vendila sul carico vero (CNN/fuso). L’epoca CPU “uccisa” è un’epoca reale interrotta, non simulata: parte sul serio, arranca, la fermi → rerun con cpu = FALSE, stesso codice, cambia solo l’acceleratore. Su questa macchina di build gira solo in lettura (eval false).

Step 03 · LLM as typed ETL

Objectives. Turn an LLM into a reproducible ETL, not a chat.

  • A typed schema (type_object()) is the contract: declare fields + R types \(\to\) every note comes back as the same validated record.
  • One live structured extraction (first note); the batch purrr::map is written, not run.
  • temperature = 0 = deterministic ETL (same input \(\to\) same record).

Voce docente (IT): hands-on (~36 min). L’LLM NON è una chat: è un ETL tipizzato e riproducibile. Min-112 (predict-output): struttura del record type_object() — 4 campi (age integer, ejection_fraction number, on_betablocker boolean, primary_dx enum a 4 valori) + cosa fa l’enum se il campo manca (vincola a lista chiusa; opzionali → NA, record resta valido). Modello reale: gpt-5.4-nano. Una sola estrazione live, il batch map è write-only.

The schema is the contract

A chat returns prose you must re-parse; an ETL returns a record. The schema is the difference.

  • type_object() declares each field + its R type — e.g. age = type_integer("patient age in years").
  • An enum (type_enum) is a guard rail: primary_dx can only be one of a closed list, never "probably cardiomyopathy".
  • Optional fields (EF not stated, beta-blocker not mentioned) come back as NA — the record stays valid.
  • The batch is written, not run: map() iterates note-by-note into a tidy tibble; temperature = 0 keeps it deterministic.

Honesty (carried forward). With no API key, we show a labeled cached result from an earlier live run — never a faked record. The key lives only in a gitignored .Renviron.

Voce docente (IT): min-124 (MCQ). temperature bassa + map: ✓ determinismo (ETL) + iterazione elemento-per-elemento. Distrattori: “temp = qualità” (NO), “temp alta + map su GPU” (NO), “temp irrilevante per extraction” (NO). La cache etichettata è la stessa dottrina dell’opzione-B: un vero record salvato prima, mostrato con etichetta, mai finto.

Step 04 · Reproducibility capstone

Objectives. Make the whole story reproducible by construction — and auditable.

  • Read the targets DAG (tar_visnetwork()): every analysis is an explicit, inspectable intermediate target you can tar_read() on its own — cohort, model, explanation.
  • The pipeline compiles the report itself: a final report target renders the Quarto doc from those intermediates, so the document and its inputs can never disagree.
  • A second tar_make() is all-skip — input hashes unchanged ⇒ reproducibility, not fakery.

Voce docente (IT): capstone (~20 min, demo). REFRAME (feedback #13): il punto di targets NON è “cache così il report è veloce”. È: (1) ogni analisi è un TARGET INTERMEDIO esplicito, ispezionabile con tar_read() uno per uno (audit per-step); (2) la PIPELINE COMPILA IL REPORT (tar_quarto/tar_render), che legge i target — così documento e input non possono divergere; (3) il 2° tar_make() è all-skip per hash invariati = riproducibilità, non finzione. PROVA col valore di ritorno, non col messaggio: tar_outdated() == character(0) e tar_progress() tutti “skipped”. Il bridge explanation ricalcola DAVVERO la VIMP → ejection_fraction / serum_creatinine / age. Stretch Davide: il device GPU è un input CIECO se non è un target.

Why a pipeline, not a hand-made cache

In Basic, the report ran the whole analysis on render — perfect at N=299. As analyses grow heavy, you do not start hand-saving .rds files and reloading them (that breaks the guarantee that the numbers came from this run). You reach for a pipeline.

  • Inspectable intermediates. Each step is a named target — cohort, model, explanation — that you can tar_read() and audit in isolation, without re-running the rest.
  • The pipeline compiles the report. A report target (tarchetypes::tar_quarto()) renders the document from the upstream targets, so what the report shows is exactly what the pipeline produced — auditable end to end.
  • Caching that stays honest. A re-run rebuilds only what changed (hash-checked) and skips the rest. That is caching with reproducibility — the opposite of a stale hand-made .rds.

Voce docente (IT): nuova slide che esplicita il principio del feedback #13. Differenza chiave dal Basic: lì il qmd FA tutto al render (giusto, a N piccolo). Qui, per analisi pesanti, la pipeline tiene target intermedi esplorabili (audit per-step) E compila il report dai target (tar_quarto), e ricostruisce solo ciò che cambia. Cache onesta, non .rds a mano.

You can hand this pipeline to a peer

The capstone payoff: this reproducible explain \(\to\) deep \(\to\) LLM pipeline is sealed.

  • A peer can clone the folder, run tar_make(), and re-derive the same explanation of the Basic model — deterministically, hash-checked.
  • Basic promised that Advanced would reload its validated model. We delivered: day one reopened that exact final_fit, and we never retrained it.

The loop is closed — from a validated model to a reproducible pipeline a colleague can re-run.
