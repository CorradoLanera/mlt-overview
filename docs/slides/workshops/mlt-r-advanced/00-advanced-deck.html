Step 01 · Interpretability

Why this step. A probability is not an explanation. We open the black box with two model-agnostic tools (permutation VIMP and SHAP), anchored on a logistic model we can read, so we can trust them on the forest we cannot.

How permutation VIMP works: a recall from ch. 4

From the theory (ch. 4): importance is how much the model leans on a feature.

  • Take the validated model and its score (AUC-ROC). Shuffle one feature’s column across patients: its signal is gone, everything else intact. Re-score.
  • The drop is that feature’s importance, \(\text{imp}(X_j) = \text{AUC} - \text{AUC}_{\text{shuffled } j}\). Repeat nsim times and average (one shuffle is noisy).
  • A big average drop means the model relies on \(X_j\). Reliance, not causation, and unsigned (a forest permutation score has no direction).

Voce docente (IT): richiamo cap.4, min-~22, prima dell’MCQ. Permuta una colonna, misura il calo di AUC-ROC, media su nsim. Build reale: in cima ejection_fraction e serum_creatinine (con age). Prepara i distrattori B (causazione) e C (segno): la VIMP a permutazione non ha segno.

How agnostic SHAP works: recall ch. 4, and how it’s computed

From the theory (ch. 4): a Shapley value \(\phi_j\) is feature \(j\)’s fair share of this prediction’s gap from the average. Additive: \(\sum_j \phi_j = f(x) - \mathbb{E}[f]\).

How an agnostic explainer computes it (model-blind, predictions only):

  • a feature’s marginal contribution as it joins coalitions of the others;
  • the “average” is taken over a background set bg_X (reference patients): the baseline the attribution is measured against;
  • permshap() enumerates exactly (small feature counts, the linear anchor); kernelshap() samples coalitions (it scales to the forest).

So the only settings are which patient (X), the background (bg_X), and how hard you sample. They trade variance for cost; none makes the answer more correct.

Agnostico: contributo marginale su coalizioni, media sul background bg_X. permshap esatto sul lineare, kernelshap campionato sull’RF. Sole leve: X, bg_X, sforzo di campionamento. SHAP settings: variance vs. cost

Three settings govern an agnostic SHAP run. None of them is a quality dial.

setting what it is the tradeoff
background (bg_X) reference rows SHAP integrates over larger \(\to\) lower-variance attributions, higher cost; tiny \(\to\) cheap but noisier
which rows (X) the patients you explain a waterfall explains one row; pick the case(s) you actually care about
exact vs. sampling how Shapley values are computed permshap() exact for small \(p\) / the linear anchor; kernelshap() hybrid/sampling as \(p\) (the number of features) grows
  • Smaller background is not “more accurate”; it is cheaper and noisier.
  • With 11 features the exact enumeration gets expensive \(\to\) the forest uses the hybrid kernelshap().

MLP hyperparameters — and the overfit cure

A small brulee MLP has four primary hyperparameters (plus two minor). With generous defaults a small net overfits this 299-patient cohort — and the cure is always the same.

hyperparameter what it controls bias / variance
epochs how long it trains too many \(\to\) fits noise (overfit)
learn_rate step size of each update too high \(\to\) diverges; too low \(\to\) underfits in budget
hidden_units capacity (width) more \(\to\) lower bias, higher variance
penalty weight decay (regularization) \(\uparrow\) penalty \(\to\) more bias, less variance
  • Minor settings: batch (gradient noise) and activation (nonlinearity) — not regularizers.
  • Overfit cure: turn penalty up and hidden_units down (or cut epochs).

The forward() of the fused network is scrambled. Put these six lines in execution order:

(a)  self$head(torch_cat(list(t, c, r), dim = 2))
(b)  t <- self$tab(x_tab)
(c)  r <- self$rnn(x_seq)

(f)  forward = function(x_tab, x_sig, x_seq) {

Then: (1) branch widths are 16, sig_ch, hidden — what must the head’s input dim equal? (2) The head emits 2 logits — what’s the output shape for a batch of \(B = 5\)?

Voce docente (IT): Parsons min-80 (Engage). (d) è il distrattore (concat senza head). Errori comuni: concat prima dei tre rami, o head prima del concat → shape error a runtime.

The answer — branches first, then concat + head

Order: f → b → e → c → a (build t, c, r in any order, then concat + head in one call):

forward = function(x_tab, x_sig, x_seq) {
  t <- self$tab(x_tab)   # [B, 16]
  c <- self$cnn(x_sig)   # [B, sig_ch]
  r <- self$rnn(x_seq)   # [B, hidden]
  self$head(torch_cat(list(t, c, r), dim = 2))
}

Head input dim: 16 + sig_ch + hidden — torch_cat(dim = 2) concatenates along the feature axis; any mismatch errors at the first forward pass. Output shape: [5, 2] — one row per observation, two logits per row (batch is always dim = 1).

The schema is the contract

A chat returns prose you must re-parse; an ETL returns a record. The schema is the difference.

  • type_object() declares each field + its R type — e.g. age = type_integer("patient age in years").
  • An enum (type_enum) is a guard rail: primary_dx can only be one of a closed list, never "probably cardiomyopathy".
  • Optional fields (EF not stated, beta-blocker not mentioned) come back as NA — the record stays valid.
  • The batch is written, not run: map() iterates note-by-note into a tidy tibble; temperature = 0 keeps it deterministic.

The reveal — four fields, graceful absence

Fields / R types: age → integer; ejection_fraction → declared type_number, but arrives as integer for a whole-number JSON value (e.g. 30) or double if decimal; on_betablocker → logical; primary_dx → character (one enum value, or NA/NULL if absent). Four fields.

Step 04 · Reproducibility capstone

Why this step. A pipeline a colleague cannot re-run is not reproducible. targets makes the whole explain→deep→LLM story re-derivable by construction: inspectable intermediate targets, a report the pipeline compiles itself, and an all-skip re-run that proves nothing drifted.

  • Read the targets DAG (tar_visnetwork()): every analysis is an explicit, inspectable intermediate target you can tar_read() on its own — cohort, model, explanation.
  • The pipeline compiles the report itself: a final report target renders the Quarto doc from those intermediates, so the document and its inputs can never disagree.
  • A second tar_make() is all-skip — input hashes unchanged ⇒ reproducibility, not fakery.

Voce docente (IT): capstone (~20 min, demo). REFRAME (feedback #13): il punto di targets NON è “cache così il report è veloce”. È: (1) ogni analisi è un TARGET INTERMEDIO esplicito, ispezionabile con tar_read() uno per uno (audit per-step); (2) la PIPELINE COMPILA IL REPORT (tar_quarto/tar_render), che legge i target — così documento e input non possono divergere; (3) il 2° tar_make() è all-skip per hash invariati = riproducibilità, non finzione. PROVA col valore di ritorno, non col messaggio: tar_outdated() == character(0) e tar_progress() tutti “skipped”. Il bridge explanation ricalcola DAVVERO la VIMP → ejection_fraction / serum_creatinine / age. Stretch Davide: il device GPU è un input CIECO se non è un target.

Why a pipeline, not a hand-made cache

In Basic, the report ran the whole analysis on render — perfect at N=299. As analyses grow heavy, you do not start hand-saving .rds files and reloading them (that breaks the guarantee that the numbers came from this run). You reach for a pipeline.

  • Inspectable intermediates. Each step is a named target — cohort, model, explanation — that you can tar_read() and audit in isolation, without re-running the rest.
  • The pipeline compiles the report. A report target (tarchetypes::tar_quarto()) renders the document from the upstream targets, so what the report shows is exactly what the pipeline produced — auditable end to end.
  • Caching that stays honest. A re-run rebuilds only what changed (hash-checked) and skips the rest. That is caching with reproducibility — the opposite of a stale hand-made .rds.

Voce docente (IT): nuova slide che esplicita il principio del feedback #13. Differenza chiave dal Basic: lì il qmd FA tutto al render (giusto, a N piccolo). Qui, per analisi pesanti, la pipeline tiene target intermedi esplorabili (audit per-step) E compila il report dai target (tar_quarto), e ricostruisce solo ciò che cambia. Cache onesta, non .rds a mano.

The reveal — all-skip is reproducibility, not a cache

Every target reports skip.

The reason is input-hash checking: targets hashes each target’s inputs (function source, upstream target objects, file dependencies). Nothing changed → hashes match → re-running would reproduce the same result → it skips. That’s reproducibility (re-derivable from unchanged inputs), not a stored value.

Difference from a cache: change any input (data, code, a parameter) and the affected target + everything downstream go stale and rebuild. A cache returns a stored value regardless; targets re-derives or skips by content hash.

Going further. Swap model/final_fit.rds (a format = "file" target) → model_file re-hashes → model → the explanation bridge rebuild; cohort stays skip. Edit the VIMP knobs inside explain_model() → only explanation rebuilds. And the GPU device is an ambient input (cuda_is_available() inside the function body) — invisible to the DAG unless promoted to a tar_target(device, ...).
