# Item 02 — Dangerous-by-default step: a quarterly SSI report

**ID**: IB-09-agents-02
**Learning objective**: Map an agent workflow's steps to the chapter's $2 \times 2$ trust-boundary grid (axes: **reversibility** × **human-in-the-loop**) and identify the *dangerous-by-default* step — the unique cell where *irreversible* $\wedge$ *no-HITL* meet. Recognise that the chapter's rule is *safe-by-default if reversible **or** human-in-the-loop*, so only **one** of the four cells is dangerous (Obj. 2).

**Category**: Application
**Type**: MCQ (scenario)
**Difficulty**: medium
**Chapter**: 09-agents

## Question

A clinical-quality team has built an agent to automate a quarterly **surgical-site infection (SSI) report**. Once configured, the agent runs the following four steps on its own, **no human reads any output between steps**:

1. **Query the EHR data warehouse** for the previous quarter's surgical-site infection cases (a `SELECT` against the warehouse — read-only access; an audit-log entry is automatically generated by the warehouse, as for every query).
2. **Compute infection rates and $95\%$ confidence intervals** by surgical department, in memory.
3. **Export the resulting summary table as a CSV** to the team's analytics folder on the shared drive (a folder that ten team members have read+write access to; files in the folder are visible immediately to anyone watching it).
4. **Post a notification message** on the team's Microsoft Teams channel **via incoming webhook**: *"New SSI report is ready in the analytics folder."* (Webhook-posted messages cannot be deleted via the Teams API once posted; manual deletion through the Teams UI is restricted to channel owners and, even then, notifications and mobile push events have already fired.)

Applying the chapter's $2 \times 2$ trust-boundary test (*reversibility* — can the action be undone in $\sim 30$ seconds? — and *human-in-the-loop* — did a human read the agent's reasoning *before* the action happened?), **which step is the *dangerous-by-default* step** — the one that *must* be gated before the agent is allowed to run unattended?

## Options

- A) **Step 1** — the database query. Because the query reads sensitive patient data (PHI) and writes a permanent entry to the warehouse's audit log, it is the step that crosses the trust boundary first and must be gated.
- B) **Step 3** — the CSV export to the shared drive. The moment the file appears in the analytics folder, ten team members can see it; the action is irreversible because *you cannot un-see what others have already seen*.
- C) **Step 4** — the Teams webhook notification. The moment the webhook delivers the message, Teams' servers broadcast notifications and mobile pushes to the team; webhook-posted messages cannot be deleted via the API, and even if a channel owner deletes the message through the Teams UI within $30$ seconds, the notifications and mobile pushes have already fired and cannot be recalled.
- D) **All four steps** are dangerous-by-default, because the agent runs all of them *unattended* (no human-in-the-loop on any step); the chapter's rule says a step needs *both* reversibility *and* human-in-the-loop to be safe.

## Expected answer

**Correct: C.** Only Step 4 sits in the *bottom-right* quadrant of the $2 \times 2$ grid — *irreversible $\wedge$ no-HITL*. The chapter's rule states a step is **safe by default if it is reversible *or* human-in-the-loop**; equivalently, it is *dangerous by default* if and only if it is *neither*. Apply this to each step:

- **Step 1** — *reversible*: the `SELECT` has no external effect on the world; the query result lives in the agent's memory and can be discarded. The audit-log entry is a *side-effect of the warehouse's record-keeping system*, not an action the agent took on the world. The agent did not *write* to the EHR; it *read* from it. → reversible $\Rightarrow$ **safe-by-default**, regardless of HITL.
- **Step 2** — *reversible*: in-memory computation; no external state changed. → reversible $\Rightarrow$ **safe-by-default**.
- **Step 3** — *reversible* by the chapter's $30$-second test: the agent's *action* is *writing a file*; the chapter's test asks *can you undo the action* (i.e., delete the file from the shared drive in $\sim 30$ seconds?) — and yes, you can. The fact that ten teammates *might* see the file in the meantime is a *consequence* of the action, not the action itself. The chapter is explicit about this distinction in the discussion of the bottom-right quadrant: *visible* is not the same as *consequential*; *consequential* is *irreversible*. → reversible $\Rightarrow$ **safe-by-default**.
- **Step 4** — *irreversible*: the moment the Teams webhook delivers the message, notifications dispatch (badge counts update on ten phones, the desktop client toasts, mobile push notifications fire); webhook-posted messages cannot be deleted via the API, and even an admin deletion through the Teams UI within $30$ seconds does not recall the already-dispatched notifications. The action and its propagation are tightly coupled — the *send* itself is the broadcast. → irreversible $\wedge$ no-HITL $\Rightarrow$ **dangerous by default**.

The single gate goes **before Step 4**. The chapter's operational rule — *ask before any irreversible action* — places the guard exactly where reversibility fails, and only there. Steps 1, 2, and 3 may run on their own at agent speed; Step 4 must pause, render the message it is about to send, and wait for a human read.

Why the distractors are plausible but wrong:

- **A** is wrong because it confuses **sensitivity** (the data is PHI, the access is auditable) with **reversibility** (can the action be undone?). The chapter's test is operational, not normative: a step is reversible if *you can delete or roll back what the agent just did*. A `SELECT` against the warehouse does not change the world — the warehouse looks the same after the query as before. The audit log is not the agent's effect; it is the warehouse's record-keeping. A student who picks A has read *"sensitive data"* as *"dangerous step"* — a clinical intuition that is *true* in many compliance contexts but is *not* what the chapter's $30$-second reversibility test measures. (The teacher's reveal can name this as the chapter's first deliberate over-simplification: privacy and reversibility are *different axes* and must be reasoned about separately — but the chapter is teaching reversibility here, not privacy governance.)
- **B** is the **subtlest distractor** because it correctly identifies that *something visible to others* has happened, but **misapplies the chapter's test**. The chapter is explicit: reversibility is whether **you** can undo the action in $\sim 30$ seconds (delete the file, close the tab, roll back the draft). For a file on a shared drive, **you can**. Teammates *might* have downloaded it in the meantime, but **the chapter does not test for downstream consequences**; it tests for *whether the action is reversible*. The phrase *"you cannot un-see what others have already seen"* is exactly the *consequence*-based reading the chapter argues against. A student who picks B has, in effect, dissolved the chapter's reversibility test into *"could this have any downstream effect at all?"* — and at that resolution, no agent step is ever reversible, and the rule becomes useless. The chapter is sharper than that: *the action is the file write; the consequence is people seeing it. The first is reversible; the second is not the test.* A student who picks B has *correctly identified that something external has happened* (which is real) but has *not correctly applied the chapter's specific test*. In correction, this is a *productive* error to surface — the difference between *the action is irreversible* (Teams webhook send) and *the action's consequences may not be undoable* (CSV-on-shared-drive) is the very distinction the chapter is teaching.
- **D** is wrong because it **reads the safe-by-default rule conjunctively** (*requires reversible AND HITL*) instead of **disjunctively** (*requires reversible OR HITL*). The chapter is unambiguous: three of the four cells of the $2 \times 2$ grid are *safe-by-default* — *reversible $\wedge$ HITL*, *reversible $\wedge$ no-HITL*, *irreversible $\wedge$ HITL*. Only *irreversible $\wedge$ no-HITL* is dangerous. A student who picks D has *gated every step* and would paralyze the agent — the operational equivalent of the *paralyzingly conservative* placement the chapter's pre-hook from cap. 08 explicitly warns against (*"the agent stops being useful"*). Picking D shows a *correct intuition about caution* but a *misreading of the rule's logical form*: the chapter's rule has a single OR in it, and D has substituted an AND. The fix is to re-read the rule and notice that **safe** requires only *one* of the two conditions, not *both*.

The single discriminator across A/B/C/D is whether the student reads the chapter's reversibility test **as the chapter states it** — *can YOU undo THIS ACTION in $\sim 30$ seconds* — versus reading it in any of three near-but-wrong ways: as *"is the data sensitive?"* (A), as *"can the action's consequences be undone?"* (B), or as *"is anything running unattended?"* (D, which collapses the rule into a single-axis test). Only C reads the test in its operational form.
